## Шаг 1. Уточнение границ разработки и DoD (Scope + Definition of Done)

### 1.1 Must / Should / Could-функции для демоверсии

#### Must (ядро) — 8 историй, без которых end-to-end не проходит

| ID | User Story | Сценарий шаг |
|----|------------|---------------|
| US-M1 | Как **хост**, я могу зарегистрироваться (email/пароль) и попасть в главное меню (FR-1.1) | Вход |
| US-M2 | Как **хост**, я могу создать комнату и получить 6-символьный код + готовый текст для пересылки + QR (FR-2.1, B-02) | Создание |
| US-M3 | Как **игрок**, я могу подключиться к комнате по коду со своего смартфона; ввод нормализуется (trim + uppercase, B-04) | Подключение |
| US-M4 | Как **хост**, я вижу лобби с обновляющимся списком игроков; запускаю партию, когда подключилось ≥ 5 (FR-2.4, FR-3.1) | Лобби |
| US-M5 | Как **игрок**, я получаю свою роль (Мафия / Шериф / Доктор / Мирный) — видна только мне (FR-3.3, FR-3.4) | Раздача ролей |
| US-M6 | Как **все игроки**, я слышу голосовое утреннее объявление с задержкой < 300 мс; на iOS Safari работает через user-gesture trigger (B-03) | Объявление ночи |
| US-M7 | Как **игрок**, я выполняю ночное действие (Мафия — выбор жертвы, Шериф — проверка, Доктор — лечение) на своём экране (FR-4.2, FR-5.2) | Ночные действия |
| US-M8 | Как **все игроки**, я участвую в дневном голосовании и вижу финал партии с раскрытием ролей (FR-4.4, FR-4.6) | Голосование + финал |

#### Should — 4 истории, улучшают доставку ценности

| ID | User Story | Зачем |
|----|------------|--------|
| US-S1 | Как **хост**, я могу нажать «Сыграть снова с теми же игроками» — без нового кода (FR-11.1, B-06) | M1-retention групп |
| US-S2 | Как **игрок**, я вижу inline-таймер на ночные действия (B-14) | Закрывает паттерн P9 пилота |
| US-S3 | Как **доктор**, я вижу чёткую подсказку «можешь лечить себя» (B-14) | Закрывает паттерн P4 |
| US-S4 | Как **игрок**, я могу выполнить `/rejoin` после разрыва Wi-Fi (FR-7.4) | Реальные сети нестабильны |

#### Could — то, что НЕ входит в текущий блок 29–32

- 2-й голосовой характер «Весёлый» (требует студии — спринт 3)
- Реферальный механизм «Пригласи 3 друзей»
- B2B-кабинет с brandbook-настройками
- Доп. роли (Маньяк, Комиссар, Любовница)
- Лендинг и Telegram Ads
- D&D-режим
- Локализация EN/KZ

### 1.2 Definition of Done для демоверсии (13 пунктов)

1. End-to-end сценарий проходит без блокирующих ошибок на Chrome desktop, Safari iOS 17+, Chrome Android 13+
2. Реализованы все 8 Must-историй (US-M1…M8)
3. Реализовано ≥ 3 из 4 Should-историй (US-S1…S4)
4. Есть пустые состояния (лобби с 0 игроков, после `/rejoin` потеряли соединение)
5. Есть обработка ошибок (неверный код комнаты, попытка дублирующего входа, потеря Wi-Fi)
6. Сохранение данных в PostgreSQL предсказуемо: после перезапуска бэка партия восстанавливается
7. Mp3-озвучка воспроизводится с задержкой ≤ 300 мс (NFR-01); 2–3 варианта фразы на каждый триггер
8. Подготовлена инструкция использования (1–2 страницы)
9. Подготовлен демо-скрипт на 90 секунд (для жюри и инвесторов)
10. Подготовлен список ограничений демоверсии (что сознательно НЕ сделано)
11. Подготовлен чек-лист тестирования из 25+ пунктов
12. Все Must-функции прошли ручное тестирование на 3 устройствах (iPhone, Android, ноутбук) — статус OK
13. Себестоимость 1 партии подтверждена ≤ 1 ₽ (Yandex Cloud + CDN; pre-recorded mp3, без TTS в рантайме)

## Шаг 2. Ключевой сценарий и контрольные точки

### 2.1 Основной end-to-end сценарий (12 шагов)

| # | Шаг | Кто | Действие | Что происходит в системе |
|---|------|------|----------|---------------------------|
| 1 | **Триггер** | Хост | Открывает `aigamemaster.ru` | Главная: кнопки «Создать», «Присоединиться», «Войти» |
| 2 | **Авторизация** | Хост | Регистрируется email/паролем | FastAPI создаёт User, выдаёт JWT (FR-1.1) |
| 3 | **Создание комнаты** | Хост | Нажимает «Создать», выбирает N (5–20), характер | Backend создаёт Room, генерирует 6-символьный код, возвращает QR + готовый текст |
| 4 | **Распространение кода** | Хост | Копирует ссылку → пересылает в общий Telegram-чат | — |
| 5 | **Подключение игроков** | Игроки 2…N | Заходят на сайт, вводят код (auto-trim + uppercase) | WebSocket-event `player_joined`; обновление лобби у всех |
| 6 | **Лобби** | Все | Видят список подключённых, статус «Готово к старту: N/N» | Кнопка «Старт» активна для хоста при N ≥ 5 |
| 7 | **Старт партии** | Хост | Нажимает «Старт» | Backend проверяет FR-3.1, выполняет случайное распределение ролей, создаёт первую ночную фазу |
| 8 | **Раздача ролей** | Все | На экране каждого игрока — его роль (только ему) | Pre-recorded mp3 «Тебе досталась роль…» + кнопка «Понял» |
| 9 | **Ночная фаза** | Игроки + Mafia/Sheriff/Doctor | Голосовое «Город засыпает» + специальные роли делают выбор | Backend собирает все action, считает итог |
| 10 | **Утреннее объявление** | Все | Mp3-фраза «Этой ночью покинул нас…» с задержкой < 300 мс | На iOS — после первого user-gesture (нажатие «Готов» на ш. 8) |
| 11 | **Дневное голосование** | Все живые | Кнопки с именами живых игроков | Backend подсчитывает голоса, фиксирует результат |
| 12 | **Финал партии** | Все | После каждой фазы — проверка FR-4.6. При условии победы — финальный mp3-монолог + таблица ролей | Кнопка «Сыграть снова с теми же» (US-S1) |

### 2.2 Контрольные точки (где замеряем прогресс / потери)

| Точка | Метрика | Триггер потери (где может застрять) |
|-------|---------|---------------------------------------|
| **CP-1** | Регистрация → Создание комнаты | Хост не понял, как создать комнату |
| **CP-2** | Создание → Подключение ≥ 5 игроков | Друзья не вошли по коду (B-04: пробелы / regex) |
| **CP-3** | Старт партии (роли розданы) | Все нажали «Понял» |
| **CP-4** | Первое утреннее объявление слышно у всех | На iOS Safari блок autoplay (B-03) |
| **CP-5** | Ночное действие совершено всеми спецролями | Доктор/Шериф не сделали выбор за 45 сек |
| **CP-6** | Финал партии достигнут | NSM-base: партия завершена без блокирующих ошибок |

### 2.3 Альтернативный сценарий: потеря соединения и `/rejoin`

| # | Шаг | Описание |
|---|------|----------|
| 1 | **Триггер** | Игрок «Маша» теряет Wi-Fi во время ночной фазы. WebSocket разорван |
| 2 | **Backend** | Сохраняет ход партии независимо; пометит Машу как `temporarily_offline` |
| 3 | **На устройстве Маши** | Показывается уведомление «Соединение потеряно. Переподключаемся…» |
| 4 | **Маша** | Wi-Fi восстановился, на сайт автоматически отправляется reconnect-запрос с её JWT |
| 5 | **Backend** | Восстанавливает её состояние (роль, фаза, текущее действие); пересылает все события, которые она пропустила |
| 6 | **На устройстве Маши** | Возврат на корректный экран по её роли и текущей фазе (FR-7.4) |
| 7 | **Если уже пропустила ход** | Помечается как «пропустила ночь», игра продолжается |

### 3.2 Модель данных (8 сущностей, PostgreSQL)

```
User
├── id (UUID, PK)
├── email (VARCHAR, UK, NOT NULL)
├── password_hash (VARCHAR, NOT NULL)
├── created_at (TIMESTAMP)
└── subscription_status (ENUM: free | pro | expired)

Room
├── id (UUID, PK)
├── code (VARCHAR(6), UK)
├── host_user_id (UUID, FK → User)
├── status (ENUM: waiting | active | finished)
├── max_players (INT, 5–20)
├── voice_character (VARCHAR: zlovesh | vesely)
├── created_at, started_at, ended_at (TIMESTAMP)

Player
├── id (UUID, PK)
├── room_id (UUID, FK → Room)
├── user_id (UUID, FK → User; nullable для anonymous-join)
├── display_name (VARCHAR(32))
├── role_id (UUID, FK → Role; NULL до старта)
├── status (ENUM: alive | dead | offline)
├── join_order (INT)

Role (справочник)
├── id (UUID, PK)
├── name (mafia | sheriff | doctor | civilian)
├── team (city | mafia)
├── night_action_type (kill | check | heal | none)

GamePhase
├── id (UUID, PK)
├── room_id (UUID, FK)
├── phase_type (night | day | voting | final)
├── phase_number (INT)
├── started_at, ended_at

NightAction
├── id (UUID, PK)
├── phase_id (UUID, FK → GamePhase)
├── actor_player_id (UUID, FK → Player)
├── target_player_id (UUID, FK → Player)
├── action_type (kill | check | heal)
├── created_at

Vote
├── id (UUID, PK)
├── phase_id (UUID, FK → GamePhase)
├── voter_player_id (UUID, FK → Player)
├── target_player_id (UUID, FK → Player)
├── created_at

GameEvent (event log, для reconnect)
├── id (UUID, PK)
├── room_id (UUID, FK)
├── event_type (VARCHAR: player_joined | game_started | phase_started | player_died | vote_result | game_finished | mp3_played)
├── payload (JSONB)
├── created_at (TIMESTAMP)
```

### 3.3 Контракт API (FastAPI endpoints)

| Метод + endpoint | Назначение | Auth | Возвращает |
|------------------|-------------|------|------------|
| `POST /auth/register` | Регистрация | — | `{user_id, jwt}` |
| `POST /auth/login` | Вход | — | `{jwt}` |
| `POST /rooms` | Создать комнату | JWT | `{room_id, code, qr_url}` |
| `POST /rooms/join` | Присоединиться по коду | JWT | `{room_id, player_id}` |
| `GET /rooms/:code/lobby` | Состояние лобби | JWT | `{players: [], status}` |
| `POST /rooms/:id/start` | Старт партии (только host) | JWT + host check | `{phase_id, role_for_me}` |
| `GET /games/:id/state` | Текущее состояние игры (для `/rejoin`) | JWT + player check | состояние согласно роли |
| `POST /games/:id/night-action` | Ночное действие | JWT + role check | `{accepted: true/false}` |
| `POST /games/:id/vote` | Дневной голос | JWT | `{recorded: true}` |
| `WS /games/:id/socket` | Real-time события партии | JWT | поток событий |

### 3.4 WebSocket-события (ключевые)

```
player_joined        { player_id, display_name }
game_started         { room_id, your_role }
phase_started        { phase_id, type, timer }
mp3_play             { url, trigger_type, variant_id }
action_required      { for_role, target_options }
night_result         { who_died: [], voice_url }
vote_result          { excluded_player_id, voice_url }
game_finished        { winner_team, roles_revealed, final_voice_url }
player_offline       { player_id }
player_reconnected   { player_id }
```
